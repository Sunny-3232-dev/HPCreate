## 1. リード抽出：「HPなし×口コミが良い×20万円出せる」の定義

### 1-1. スクリーニング条件（`collect.js` の `FILTER` を拡張）

| 項目 | 現行 | 新基準 | 理由 |
|---|---|---|---|
| 評価 | ★4.0以上 | ★4.2以上 | 「口コミが良い」を明確に |
| 口コミ数 | 3件以上 | **10件以上**（Bランク5件以上） | 件数＝来店・施工実績＝売上規模の代理指標 |
| Web | websiteUri なし | websiteUri なし **または** SNS/食べログ/ホットペッパーのみ | ポータル依存の店はHP需要が高い |
| 営業状態 | – | `businessStatus = OPERATIONAL` | 閉業除外 |
| エリア | 栃木中部の矩形 | 宇都宮市に絞った矩形＋住所に「宇都宮市」を含む | 対面営業を回せる範囲 |

### 1-2. 「20万円出せそう」スコア（支払い能力の代理指標）

Places API で取れる情報だけで機械的に点数化し、上位から当たる。

| 要素 | 配点 | 取得元 |
|---|---|---|
| 高単価業種（下表） | +3 | 業種タグ |
| 法人格（株式会社/有限会社）が屋号に入る | +2 | displayName |
| 口コミ30件以上 | +2 | userRatingCount |
| `priceLevel` が MODERATE 以上（飲食） | +1 | priceLevel |
| 営業日が週5日以上・駐車場あり | +1 | regularOpeningHours / parkingOptions |
| 口コミ本文に「職人」「丁寧」「また頼みたい」等 | +1 | reviews |

**7点以上＝A、5〜6点＝B**。A から訪問、B はレター送付のみ。

### 1-3. 業種を3→12に拡張（`INDUSTRIES`）

「1件の受注額が大きく、HP1本で元が取れる」業種を優先する。

| 優先 | 業種 | 20万円の回収ロジック |
|---|---|---|
| A | 工務店・リフォーム | 1件受注で数十万〜数百万。HPからの問合せ1件で回収 |
| A | 造園・外構（既存） | 同上 |
| A | 自動車整備・板金塗装 | 車検1台5〜10万。年数台で回収 |
| A | 葬儀社・仏壇・石材（既存＋） | 1件数十万〜。比較検討されるのでHP必須 |
| A | 解体（既存） | 1件100万規模 |
| B | 整体・接骨院 | 回数券・継続来院。LTVが高い |
| B | 美容室（個人経営・評価高） | 固定客化で年数万/人 |
| B | 割烹・寿司・焼肉など客単価5千円以上の飲食 | 宴会・法事予約1件で数万円 |
| B | 仕出し・弁当 | 法人・法事需要。1件数万円 |
| B | 写真館 | 七五三・成人式で1件数万円 |
| C | 畳・建具・表具・リペア | 単価は中、地域需要安定 |
| C | ペットサロン・学習塾 | 継続課金型 |

**除外**: チェーン店・フランチャイズ（本部HPあり）、屋根・外壁塗装（既に判定済み：競合多く訪問販売イメージ）。

### 1-4. 候補リスト（Web調査による一次候補）

→ `docs/CANDIDATES.md` 参照。**Web調査ベースのため、評価・件数・HP有無は Places API で再検証してから営業に使う。**

## 3. 自社HP（SunConnect）リニューアル計画

### 3-1. 現状診断（`utsunomiya-sales/public/index.html`）

良い点: 「黎明（dawn）」のブランドトーン、明朝＋Fraunces のタイポ、ストーリー構成（課題→アプローチ→実績→流れ→料金→相談）はすでに良い。

**公開前に必ず直すもの（信頼に直結）**

| # | 問題 | 対応 |
|---|---|---|
| 1 | 電話 `028-680-0000`・〒`320-0000`・`contact@sunconnect.jp` が仮値 | 実値へ差し替え（ドメイン取得状況を確認） |
| 2 | **実在の事業者（開沼園芸・茂呂造園ほか）のサンプルLPを「制作実績」として掲載**。承諾がなく受注もしていない場合、景品表示法上の誤認表示・事業者とのトラブルリスク | 「制作実績」→「提案サンプル（架空店舗）」に差し替え。実在店舗名は成約・掲載許可を得てから |
| 3 | お問合せフォームがない（電話・メールのみ） | フォーム設置（Cloudflare Pages Functions or 外部フォーム）＋LINE公式の導線 |
| 4 | `prefers-reduced-motion` 未対応 | 全モーションに対応（アクセシビリティ） |
| 5 | 料金に20万円帯の主力商品がない | §2 の「集客スタートパック」を中央・推奨表示に |
| 6 | 運営者の顔が見えない | 代表プロフィール・写真・「宇都宮在住」を明記（地方営業は人で買われる） |
| 7 | OGP・構造化データ（LocalBusiness）・favicon 未整備 | 追加（自社がSEO/MEOできていないと説得力がない） |

### 3-2. 新しいページ構成

1. **Hero** — 「朝陽が差し込むように、地方の仕事に光を。」WebGLの朝陽（後述）
2. **数字で語る課題** — 「宇都宮の★4.5のお店の◯割がHPを持っていない」（自社リード調査の実数を使う＝独自データ）
3. **Before / After** — 「Googleで屋号を検索したとき」の比較（地図だけ → HP・口コミ・写真が揃う）をスクロール連動で切り替え
4. **提案サンプル** — 業種別の架空店舗サンプル5〜6本（横スクロールのギャラリー）
5. **集客スタートパック** — 20万円の中身を分解して見せる
6. **制作の流れ** — 訪問→撮影→10営業日で公開（タイムラインがスクロールで伸びる）
7. **補助金の案内** — 持続化補助金などで実質負担が下がることを説明
8. **代表あいさつ・FAQ・お問合せフォーム**

### 3-3. モーション設計（2026年時点の最新技術を、軽さを保って使う）

| 演出 | 技術 | 補足 |
|---|---|---|
| ヒーローの朝陽（光がゆっくり揺らぐ・マウス/傾きに反応） | **WebGL フラグメントシェーダ**（OGL、約10KB） | 低スペック端末・reduced-motion時は現行のCSSグラデにフォールバック |
| 見出しの文字が1文字ずつ立ち上がる | **GSAP SplitText**（2025年から全プラグイン無償） | 日本語は文字単位で分割 |
| スクロール連動の出現・視差・タイムライン伸長 | **CSS Scroll-driven Animations**（`animation-timeline: view()` / `scroll()`） | JS不要でメインスレッドを塞がない。未対応ブラウザは GSAP ScrollTrigger で補完 |
| 慣性スクロール | **Lenis** | スマホでは無効化も検討 |
| Before/After・料金の切替 | **View Transitions API**（同一ドキュメント＋ページ間 `@view-transition`） | サンプル一覧→詳細への遷移もシームレスに |
| 要素の出現初期状態 | CSS `@starting-style` | ポップアップ・メニューの開閉 |
| ボタンの磁力・カーソル追従 | 小さなJS（PCのみ） | やりすぎない |

**性能予算（Core Web Vitals）**: LCP < 2.0秒、INP < 200ms、CLS < 0.05、JS合計 < 80KB(gzip)。フォントはサブセット化（現状5ファミリー読み込み→3つに削減）。
**アクセシビリティ**: `prefers-reduced-motion: reduce` で全演出を静止版に。

### 3-4. 技術構成

- **Astro**（静的出力）＋ GSAP / Lenis / OGL を npm で管理 → 表示は静的HTMLのまま、部品化で保守しやすく
- ホスティングは既存ルールどおり **Cloudflare Pages**、お問合せフォームは Pages Functions（送信先はメール）
- 本リポジトリ `HPCreate` を自社HP専用リポジトリにし、`utsunomiya-sales/public/` からは自社トップを切り離す（営業ツールと自社サイトの分離）
